# Meeting Room Booking System

A role-based meeting room booking platform: a FastAPI + MySQL backend with JWT
authentication, and a framework-free HTML/CSS/JS frontend that consumes it.
Three fixed roles — **Super Admin**, **Office Admin**, and **Employee** — each
get their own scoped area of the app, matching exactly what the API allows
them to do.

## Features

- **Super Admin** — create and manage offices; create and manage office
  admins (one per office).
- **Office Admin** — create and manage employees in their own office; create
  and manage that office's meeting rooms (capacity, floor, active/inactive
  status).
- **Employee** — book a meeting room in their own office, invite colleagues,
  view their upcoming and past meetings, edit or cancel meetings they
  organized. Room double-booking, past-dated bookings, and over-capacity
  bookings are all rejected server-side.
- JWT-based authentication (`Authorization: Bearer <token>`), password
  hashing via bcrypt/passlib, per-route role enforcement on every endpoint.

## Tech stack

| Layer | Technology |
|---|---|
| Backend | Python, FastAPI, SQLAlchemy ORM, MySQL (via PyMySQL) |
| Auth | JWT (`python-jose`), password hashing (`passlib` + `bcrypt`) |
| Backend tests | pytest + FastAPI `TestClient`, 100+ tests against a real MySQL test DB |
| Frontend | HTML5, CSS3 (custom properties, no preprocessor), vanilla JavaScript (ES modules) — no build step, no framework |

## Prerequisites

- Python 3.11+
- MySQL server running locally (or reachable)
- Two empty MySQL databases: one for the app, one for tests (names are
  whatever you set in `.env` / `.env.test` — tables are created
  automatically on startup, but the *databases themselves* are not)

## Setup

1. **Clone and create a virtual environment**
   ```bash
   python -m venv .venv
   .venv\Scripts\activate        # Windows
   source .venv/bin/activate     # macOS/Linux
   ```

2. **Install dependencies**
   ```bash
   pip install -r requirements.txt
   # for running the test suite too:
   pip install -r requirements-dev.txt
   ```

3. **Create the MySQL databases**
   ```sql
   CREATE DATABASE meeting_room_booking;
   CREATE DATABASE meeting_room_booking_test;
   ```

4. **Configure environment variables** — create `.env` in the project root:
   ```env
   DB_HOST=localhost
   DB_PORT=3306
   DB_NAME=meeting_room_booking
   DB_USER=root
   DB_PASSWORD=your_mysql_password

   SECRET_KEY=a-long-random-secret
   ALGORITHM=HS256
   ACCESS_TOKEN_EXPIRE_MINUTES=30

   SUPER_ADMIN_EMAIL=superadmin@yourcompany.com
   SUPER_ADMIN_PASSWORD=choose-a-strong-password
   ```
   For running tests, also create `.env.test` with the same shape but
   `DB_NAME=meeting_room_booking_test` and its own `SECRET_KEY`.

5. **Seed the first Super Admin** (subsequent runs are a no-op if one already exists):
   ```bash
   python scripts/seed_super_admin.py
   ```

## Running the app

**Backend** (from the project root):
```bash
uvicorn app.main:app --reload
```
Runs on `http://localhost:8000`. Interactive API docs are auto-generated by
FastAPI at `http://localhost:8000/docs` (Swagger UI) and `/redoc`.

**Frontend** (from `frontend/`):
```bash
cd frontend
python -m http.server 5500
```
With the backend also running, open `http://localhost:5500/index.html`. The
backend's CORS config only allows `localhost:5500` / `127.0.0.1:5500` by
default — if you serve the frontend on a different port, add it in
`app/main.py`. Full frontend details are in [`frontend/README.md`](frontend/README.md).

## Running tests

```bash
pytest -v
```
Requires the `meeting_room_booking_test` database to exist and be reachable
via `.env.test` (see Setup step 3–4). Config lives in `pyproject.toml`.

## Roles & permissions

Roles are **fixed and non-hierarchical** — each endpoint is locked to exactly
one role; there is no "admins can also do employee things" fallback.

| Role | Can manage | Cannot access |
|---|---|---|
| `SUPER_ADMIN` | Offices, Office Admins | Employees, Meeting Rooms, Bookings |
| `OFFICE_ADMIN` | Employees (own office), Meeting Rooms (own office) | Offices, Office Admins, Bookings |
| `EMPLOYEE` | Bookings (own), read-only room/colleague lookups (own office) | Offices, Office Admins, Employees, Meeting Room CRUD |

Every authenticated user can call `GET /auth/me` regardless of role.
