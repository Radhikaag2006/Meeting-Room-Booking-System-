## Authentication

Every endpoint except `POST /auth/login` requires a JWT bearer token:

```
Authorization: Bearer <access_token>
```

Get a token from `POST /auth/login`. Tokens expire after
`ACCESS_TOKEN_EXPIRE_MINUTES` (from `.env`, default 30) and encode
`user_id`, `role`, and `office_id` in the payload.

## Roles

Three fixed, **non-hierarchical** roles. Each endpoint is locked to exactly
one role — there is no "higher" role that can also call a "lower" role's
endpoints.

| Role | Value |
|---|---|
| Super Admin | `SUPER_ADMIN` |
| Office Admin | `OFFICE_ADMIN` |
| Employee | `EMPLOYEE` |

## Conventions

- All request/response bodies are JSON.
- Timestamps: dates as `YYYY-MM-DD`, times as `HH:MM:SS`.
- Standard error shape:
  ```json
  { "detail": "Human-readable message" }
  ```
- Common status codes: `200` (success), `201` (created), `400` (bad
  input/business rule violation), `401` (missing/invalid/expired token,
  or bad login credentials), `403` (authenticated but wrong role, or
  cross-office access attempt), `404` (not found), `409` (conflict — duplicate
  name/email, double-booking, etc.), `422` (request body failed schema
  validation).
- Delete endpoints return `200` with `{"message": "..."}` — not `204`.

## Auth

### `POST /auth/login`
Public. Exchanges credentials for a JWT.

**Request body**
```json
{ "email": "user@company.com", "password": "string" }
```

**Response `200`**
```json
{ "access_token": "string", "token_type": "bearer" }
```

**Errors**: `404` user not found · `401` incorrect password · `403` account
status is `INACTIVE`.

### `GET /auth/me`
Any authenticated role. Returns the caller's own profile — used by the
frontend to verify a token is still valid server-side and to determine
which role's UI to show.

**Response `200`**
```json
{
  "user_id": 1,
  "first_name": "Ada",
  "last_name": "Lovelace",
  "email": "ada@company.com",
  "role": "EMPLOYEE",
  "status": "ACTIVE",
  "office_id": 2
}
```

## Offices
All routes require `SUPER_ADMIN`. Prefix: `/offices`.

| Method | Path | Description |
|---|---|---|
| POST | `/offices/` | Create an office |
| GET | `/offices/` | List all offices |
| GET | `/offices/{office_id}` | Get one office |
| PUT | `/offices/{office_id}` | Update an office (partial) |
| DELETE | `/offices/{office_id}` | Delete an office |

**`OfficeCreate`** (POST body — all fields required)
```json
{ "office_name": "string", "address": "string", "city": "string", "state": "string", "country": "string" }
```

**`OfficeUpdate`** (PUT body — all fields optional, only send what changes)
```json
{ "office_name": "string", "address": "string", "city": "string", "state": "string", "country": "string" }
```

**`OfficeResponse`**
```json
{ "office_id": 1, "office_name": "string", "address": "string", "city": "string", "state": "string", "country": "string" }
```

**Notes**: `office_name` must be unique. `DELETE` returns
`{"message": "Office '<name>' deleted successfully."}`.

## Office Admins
All routes require `SUPER_ADMIN`. Prefix: `/office-admins`.

| Method | Path | Description |
|---|---|---|
| POST | `/office-admins` | Create an office admin |
| GET | `/office-admins` | List all office admins |
| GET | `/office-admins/{user_id}` | Get one office admin |
| PUT | `/office-admins/{user_id}` | Update an office admin (partial) |
| DELETE | `/office-admins/{user_id}` | Delete an office admin |

**`OfficeAdminCreate`**
```json
{ "first_name": "string", "last_name": "string", "email": "user@company.com", "password": "string", "office_id": 1 }
```

**`OfficeAdminUpdate`** (all optional)
```json
{ "first_name": "string", "last_name": "string", "email": "user@company.com", "status": "ACTIVE" }
```

**`OfficeAdminResponse`**
```json
{ "user_id": 1, "first_name": "string", "last_name": "string", "email": "string", "office_id": 1, "status": "ACTIVE" }
```

**Notes**: `office_id` must reference an existing office (`404` otherwise). An
office can have **at most one** office admin — creating a second for the
same office returns `409`. Email must be globally unique (`409`).

## Employees
Prefix: `/employees`.

| Method | Path | Role | Description |
|---|---|---|---|
| POST | `/employees` | `OFFICE_ADMIN` | Create an employee in the caller's own office |
| GET | `/employees` | `OFFICE_ADMIN` | List employees in the caller's own office |
| GET | `/employees/colleagues` | `EMPLOYEE` | List **active** colleagues in the caller's own office (excludes the caller) — used for the booking attendee picker |
| GET | `/employees/{user_id}` | `OFFICE_ADMIN` | Get one employee (must be in the caller's office) |
| PUT | `/employees/{user_id}` | `OFFICE_ADMIN` | Update an employee (partial) |
| DELETE | `/employees/{user_id}` | `OFFICE_ADMIN` | Delete an employee |

**`EmployeeCreate`** — no `office_id` field; it's taken from the creating
office admin automatically.
```json
{ "first_name": "string", "last_name": "string", "email": "user@company.com", "password": "string" }
```

**`EmployeeUpdate`** (all optional)
```json
{ "first_name": "string", "last_name": "string", "email": "string", "status": "ACTIVE" }
```

**`EmployeeResponse`**
```json
{ "user_id": 1, "first_name": "string", "last_name": "string", "email": "string", "office_id": 1, "status": "ACTIVE" }
```

**Notes**: an `OFFICE_ADMIN` can only see/manage employees in their **own**
office — `get_employee_by_id` on another office's employee returns `404`,
not `403` (doesn't reveal the employee exists elsewhere). `GET
/employees/colleagues` is intentionally the only route on this router an
`EMPLOYEE` can call.

## Meeting Rooms
Prefix: `/meeting-rooms`.

| Method | Path | Role | Description |
|---|---|---|---|
| POST | `/meeting-rooms` | `OFFICE_ADMIN` | Create a room in the caller's own office |
| GET | `/meeting-rooms` | `OFFICE_ADMIN` | List all rooms in the caller's own office |
| GET | `/meeting-rooms/available` | `EMPLOYEE` | List **active** rooms in the caller's own office — used for the booking room picker |
| GET | `/meeting-rooms/{room_id}` | `OFFICE_ADMIN` | Get one room (must be in the caller's office) |
| PUT | `/meeting-rooms/{room_id}` | `OFFICE_ADMIN` | Update a room (partial) |
| DELETE | `/meeting-rooms/{room_id}` | `OFFICE_ADMIN` | Delete a room |

**`MeetingRoomCreate`**
```json
{ "room_name": "string", "capacity": 10, "floor": 2 }
```
New rooms default to `status: "ACTIVE"`.

**`MeetingRoomUpdate`** (all optional)
```json
{ "room_name": "string", "capacity": 10, "floor": 2, "status": "ACTIVE" }
```
`status` is one of `"ACTIVE"` / `"INACTIVE"`.

**`MeetingRoomResponse`**
```json
{ "room_id": 1, "office_id": 1, "room_name": "string", "capacity": 10, "floor": 2, "status": "ACTIVE" }
```

**Notes**: `room_name` must be unique within the office. `capacity > 0` and
`floor >= 0` are enforced (`400` otherwise). Deactivating a room (`status:
"INACTIVE"`) immediately removes it from `GET /meeting-rooms/available`
(and therefore the employee booking flow) without deleting it — existing
bookings against it are unaffected.

## Bookings
All routes require `EMPLOYEE`. Prefix: `/bookings`.

| Method | Path | Description |
|---|---|---|
| POST | `/bookings` | Create a booking (caller becomes the organizer) |
| GET | `/bookings/my-meetings` | List bookings where the caller is organizer or an invited attendee |
| GET | `/bookings/{booking_id}` | Get one booking (organizer or attendee only) |
| PUT | `/bookings/{booking_id}` | Update a booking (**organizer only**) |
| PATCH | `/bookings/{booking_id}/cancel` | Cancel a booking (**organizer only**) |

**`BookingCreate`**
```json
{
  "meeting_title": "string",
  "description": "string or null",
  "room_id": 1,
  "meeting_date": "2026-08-01",
  "start_time": "10:00:00",
  "end_time": "11:00:00",
  "attendees": [3, 4]
}
```
`attendees` is a list of employee `user_id`s to invite (can be empty — the
organizer is always added automatically). Room and attendees must belong to
the same office as the caller.

**`BookingUpdate`** (all optional — organizer only)
```json
{
  "meeting_title": "string",
  "description": "string",
  "room_id": 1,
  "meeting_date": "2026-08-01",
  "start_time": "10:00:00",
  "end_time": "11:00:00",
  "status": "SCHEDULED"
}
```
Note: attendees cannot be changed after creation (no `attendees` field in
`BookingUpdate`) — the API has no endpoint for it.

**`BookingResponse`**
```json
{
  "booking_id": 1,
  "meeting_title": "string",
  "description": "string or null",
  "room_id": 1,
  "meeting_date": "2026-08-01",
  "organizer_id": 5,
  "start_time": "10:00:00",
  "end_time": "11:00:00",
  "status": "SCHEDULED"
}
```
`status` is one of `"SCHEDULED"` / `"CANCELLED"` / `"COMPLETED"`. Note the
response does not include attendee names or the room's display name — resolve
those client-side via `GET /meeting-rooms/available` and `GET
/employees/colleagues`.

### Booking validation rules
Enforced server-side on `POST /bookings` (most also apply on update):

- `meeting_date` cannot be in the past.
- `start_time` must be before `end_time`.
- `attendees` cannot contain duplicates.
- `room_id` must exist, have `status: "ACTIVE"`, and belong to the caller's
  office (`403` if it belongs to another office).
- Every attendee must exist, have role `EMPLOYEE`, be `ACTIVE`, and belong
  to the caller's office.
- Capacity: attendee count (organizer included, counted once even if also
  listed in `attendees`) must not exceed the room's `capacity` (`400`).
- No double-booking: the room can't have another non-cancelled booking with
  an overlapping time range on the same date (`409`).
- `PUT`/`PATCH /cancel` on a booking you didn't organize returns `403`, even
  if you're an invited attendee.
